# Полная документация Orthosmile

Версия документа: 1 августа 2026 года.

Адрес рабочего сайта: `https://orthosmile.duckdns.org/`

Подробный технический том с разбором фактического кода, каждой backend-функции,
интерактивных элементов, JavaScript и инфраструктуры находится в
[`FULL_DOCUMENTATION_RU.md`](FULL_DOCUMENTATION_RU.md). В нем более 10 000 строк.

Эта инструкция написана для человека, который раньше не работал с программированием. Здесь сначала объясняется сайт как обычная программа, а затем постепенно разбирается его внутреннее устройство. Читать весь файл за один раз не обязательно. Для обычной работы достаточно разделов 1-8. Технические разделы нужны, чтобы понимать код, запуск, базу данных и сервер.

> Важно: настоящие пароли, токен Telegram-бота, секрет Django, пароль PostgreSQL и ключи Google в этот файл намеренно не записаны. Они находятся в закрытом файле `.env` на сервере. Такой файл нельзя отправлять посторонним и нельзя добавлять в Git.

## 1. Самое простое объяснение сайта

Orthosmile состоит из нескольких частей:

1. **Страницы в браузере** показывают текст, формы, кнопки, фото и расписание.
2. **Django** получает нажатия пользователя, проверяет права и решает, что делать.
3. **PostgreSQL** хранит пользователей, врачей, услуги, расписания, заявки и медицинские записи.
4. **Файловое хранилище** хранит фотографии, видео, логотип и фон.
5. **Google OAuth** подтверждает личность пациента.
6. **Telegram-бот** привязывается к аккаунту и отправляет уведомления.
7. **Nginx и Gunicorn** делают Django доступным в интернете по защищенному адресу.

Пример обычного действия:

1. Пациент нажимает `Надіслати заявку`.
2. Браузер отправляет заполненную форму на сервер.
3. Django проверяет пользователя, дату, дневной лимит, график врача, обед и пересечения.
4. Если все правильно, Django записывает заявку в PostgreSQL.
5. Django создает карточку пациента у врача, если ее еще нет.
6. Django пытается отправить врачу Telegram-уведомление.
7. Пациент видит темное всплывающее сообщение об успешной отправке.

## 2. Кто может пользоваться сайтом

### 2.1. Гость

Гость не вошел в аккаунт. Он может:

- смотреть главную страницу;
- читать новости клиники и врачей;
- листать галерею;
- смотреть список врачей;
- открывать подробный профиль врача;
- смотреть страницы услуг;
- начать вход через Google;
- начать регистрацию по номеру телефона;
- открыть общий вход для врача и администратора.

Гость не может создать заявку. При попытке открыть защищенную функцию сайт попросит войти через Google.

### 2.2. Временный пациент после ввода телефона

Это человек, который ввел номер телефона, но еще не связал кабинет с Google. Он видит временный кабинет и найденные по номеру будущие записи. Регистрационные кнопки на главной больше не показываются, потому что процесс уже начат.

Он может смотреть найденную информацию, но не может полноценно работать с сайтом и записываться. Для завершения ему нужно нажать `Увійти через Google`.

### 2.3. Пациент

Пациент входит через Google. У него есть профиль с именем, фамилией, телефоном, возрастом и необязательной фотографией. Пациент может:

- создавать заявки;
- прикреплять к заявке фото и видео;
- записывать не только себя, но и другого человека;
- смотреть решения врача;
- принимать или отклонять предложенный перенос;
- отменять будущую заявку или прием;
- восстанавливать отмененную заявку, пока время никто не занял;
- смотреть лечение и рекомендации;
- подключать Telegram.

### 2.4. Врач

Аккаунт врача создает администратор. Врач входит по имени пользователя и паролю через кнопку `Вхід для адміністрації`. Сайт сам понимает, что это врач, и открывает кабинет врача.

Врач может:

- принимать и отклонять заявки;
- предлагать пациенту другое время;
- самостоятельно записывать пациентов;
- видеть недельный список приемов;
- вести карточки пациентов;
- добавлять медицинские записи, фото и видео;
- настраивать места приема, расписание и обед;
- создавать и сортировать услуги;
- показывать или скрывать услуги для онлайн-записи;
- публиковать свои новости;
- редактировать свой профиль;
- подключать Telegram.

### 2.5. Администратор

Администратор тоже входит через `Вхід для адміністрації`, но после входа попадает в административную панель. Он может:

- создавать врачей;
- редактировать пользователей;
- архивировать и восстанавливать аккаунты;
- окончательно удалять только архивированных пациентов;
- отменять приемы;
- редактировать главную страницу;
- менять логотип, фон, эффекты, слайды, новости и галерею;
- смотреть журнал действий;
- открывать стандартную системную панель Django.

## 3. Как устроено меню

### 3.1. Логотип и название клиники

Нажатие на логотип или название клиники всегда открывает главную страницу.

### 3.2. Верхнее меню гостя

- `Лікарі` открывает список врачей.
- `Вхід для адміністрації` открывает единую форму входа врача или администратора.

Вход пациента расположен на главном экране и выполняется через Google.

### 3.3. Верхнее меню пациента

- `Лікарі` открывает каталог специалистов.
- `Мій кабінет` открывает кабинет пациента.
- `Записатися` открывает форму новой заявки.
- `Вийти` завершает сеанс.

Рамкой выделяется только тот раздел, в котором пользователь находится сейчас.

### 3.4. Верхнее меню врача

- `Кабінет лікаря` открывает обзор профиля врача.
- `Вийти` завершает сеанс.

Рабочие разделы врача расположены вкладками внутри кабинета.

### 3.5. Верхнее меню администратора

- `Панель адміністратора` открывает управление клиникой.
- `Вийти` завершает сеанс.

### 3.6. Ссылка возврата

Маленькая зеленая ссылка вида `← Повернутися ...` показывается только на второстепенных страницах: в деталях, редакторах и отдельных формах. На главных кабинетах и списках она не нужна.

### 3.7. Telegram-панель

Если Telegram еще не подключен, подходящий пользователь видит `Приєднати Telegram-бота`. Кнопка создает одноразовую ссылку и открывает бота. У пациента кнопка появляется только после полного Google-входа.

Если Telegram уже подключен, в карточке профиля пациента показывается зеленый статус `Бот прив’язаний` и маленькая кнопка `Переприв’язати бота`. Кнопка отправляет защищенный POST-запрос, создает новый одноразовый код, удаляет старую связь `TelegramConnection` и открывает Telegram. Пока пользователь не нажмет `Start` по новой ссылке, уведомления не доставляются. Если создать ссылку не удалось, старая связь сохраняется.

### 3.8. Зеленая панель активного приема врача

Она автоматически появляется на всех страницах врача, если сейчас идет подтвержденный прием. Кнопка просмотра открывает небольшое окно с записями этого врача о текущем пациенте. `Створити новий запис` ведет в полную карточку пациента.

## 4. Полная инструкция для посетителя и пациента

### 4.1. Главная страница

Первый экран занимает большая фотография клиники. Слайды меняются каждые 10 секунд.

- Стрелка влево показывает предыдущую фотографию.
- Стрелка вправо показывает следующую фотографию.
- Точки показывают количество фотографий и позволяют выбрать конкретную.
- Наведение мыши на слайдер временно останавливает автоматическую смену.
- При включенной системной настройке уменьшения анимации автопрокрутка отключается.

На экране показываются название Orthosmile, короткое описание, адреса `Нікополь, Шевченко 200` и `Дніпро, Гусенка 17`, а также кликабельный телефон `0509168426`.

Кнопки зависят от роли:

- Гость видит `Увійти через Google`, `Переглянути лікарів` и `Реєстрація за номером телефону`.
- Временный пациент видит `Перейти до кабінету` и `Переглянути лікарів`.
- Обычный пациент видит `Записатися на прийом` и `Переглянути лікарів`.
- Врач видит `Перейти до кабінету лікаря`.
- Администратор видит `Перейти до панелі адміністратора`.

Ниже расположены:

1. `Новини клініки` - публикации администратора.
2. `Новини лікарів` - публикации врачей.
3. `Галерея` - только фотографии, добавленные администратором. Одна большая фотография меняется каждые 5 секунд; есть стрелки и точки.
4. `Наші провідні лікарі` - до четырех активных врачей с наибольшим числом записей.
5. `Усі лікарі` - переход в полный каталог.

После прокрутки вниз появляется закрепленная верхняя шапка. В начале первого экрана она скрыта, чтобы не закрывать фотографию.

### 4.2. Вход пациента через Google

Кнопка `Увійти через Google` перенаправляет на страницу Google. Пользователь выбирает аккаунт и подтверждает вход. Пароль Google сайт Orthosmile не получает и не хранит.

После успешного входа:

- новый пользователь получает профиль пациента;
- существующий пользователь открывает прежний кабинет;
- если перед входом был введен номер, найденные записи и карточки привязываются к этому пользователю;
- имя и фамилия, ранее введенные врачом, сохраняются вместо имени из Google.

### 4.3. Регистрация по номеру телефона

Кнопка `Реєстрація за номером телефону` нужна в двух случаях:

1. Врач ранее записал человека вручную, и пациент хочет получить эти записи.
2. Человек еще не записывался, но хочет начать создание кабинета с телефона.

Действия:

1. Ввести номер.
2. Нажать `Продовжити`.
3. Сайт проверит, не принадлежит ли номер уже другому полноценному кабинету.
4. Откроется временный кабинет.
5. Нажать `Увійти через Google`.
6. После Google-входа сайт завершит привязку.

Если номер уже занят, новая привязка не создается. Пользователю предлагается войти через Google в существующий кабинет.

### 4.4. Каталог врачей

Поле `Фільтр лікарів` сразу отбирает карточки по имени, специальности или городу. Отдельная кнопка поиска не нужна.

В карточке врача:

- фото или инициалы;
- имя и фамилия;
- специальность;
- одна кнопка `Детальніше`;
- кнопка `Записатися`, если пациент уже вошел;
- `Увійти для запису`, если это гость.

### 4.5. Подробный профиль врача

Здесь показываются фото, специальность, телефон, города, текст о враче, рабочий график, услуги и новости. Длинные списки услуг можно раскрывать и сворачивать.

- `Записатися` открывает форму и заранее выбирает этого врача.
- `Детальніше` возле услуги открывает отдельную страницу услуги.
- На странице услуги показываются описание, примерная стоимость, фотографии и видео.
- `Повернутися до заявки` возвращает в форму записи и сохраняет выбранного врача, дату, время и услугу.

### 4.6. Кабинет пациента

Вкладки:

- `Огляд` перемещает к верхней части кабинета.
- `Мої заявки` перемещает к заявкам, которые ожидают решения врача.
- `Прийоми` перемещает к подтвержденным будущим приемам.
- `Лікування` перемещает к видимым пациенту материалам врача.
- `Історія` перемещает к завершенным, отмененным и отклоненным приемам.

Профильная карточка содержит фото или инициалы, имя, возраст и телефон.

- `Створити запис` открывает запись к врачу.
- `Редагувати профіль` открывает имя, фамилию, возраст, телефон и фото.
- `Змінити пароль` показывается только аккаунту с обычным паролем. При Google-входе отдельный пароль Orthosmile не нужен.

Если профиль заполнен не полностью, появляется яркое сообщение с кнопкой `Редагувати профіль`. Без имени, фамилии, возраста и телефона заявку создать нельзя.

Если врач предложил другое время, сверху появляется янтарная панель:

- `Деталі` открывает полный прием;
- зеленая круглая кнопка с галочкой принимает новый вариант;
- красная круглая кнопка с крестиком отклоняет перенос и отменяет запись.

### 4.7. Карточка заявки или приема пациента

В каждой карточке показываются фото врача, врач, специальность, услуга, дата, время, место, длительность и статус. Ближайший подтвержденный прием выделяется заметным цветом. Адрес является ссылкой: нажатие открывает Google Maps в новой вкладке с уже подготовленным поиском только по городу и улице, без названия клиники.

- `Детальніше` открывает все данные и прикрепленные пациентом материалы.
- `Скасувати` отменяет будущую заявку или прием. Время сразу освобождается.
- `Відновити` повторно отправляет отмененную заявку врачу, но только если время еще свободно.

Если освобожденное место занял другой пациент, восстановление блокируется и сайт объясняет причину.

### 4.8. Создание заявки

Форма состоит из трех шагов.

**Шаг 1. Лікар і дата**

- В поле `Лікар` выбирается врач.
- В поле `Дата` выбирается день.
- После изменения врача или даты страница автоматически обновляет профиль, график и свободное время.
- Пациент может записаться только начиная с завтрашнего дня.

**Шаг 2. Вільний час**

- Белая кнопка времени означает свободный слот.
- Приглушенная недоступная кнопка означает занятое или неподходящее время.
- Выделенная кнопка означает выбранное время.

**Шаг 3. Підтвердження заявки**

- `Послуга` содержит только услуги, которые врач разрешил выбирать пациентам.
- Фильтр услуг сразу сокращает список по названию и описанию.
- `Детальніше про послугу` открывает ее отдельную страницу, не теряя текущий выбор.
- `Причина звернення` объясняет врачу проблему или цель визита.
- `Записуюсь не я` включает поля имени и фамилии другого человека.
- `Фотографії до заявки` принимает до 6 фото.
- `Відео до заявки` принимает до 2 видео.
- `Надіслати заявку` выполняет серверные проверки и создает статус `Нова заявка`.

Пациент не выбирает длительность. Окончательную длительность определяет врач при подтверждении.

### 4.9. Лечение и рекомендации

Пациент видит только записи типов `Лікування` и `Рекомендації`. Внутренние врачебные `Нотатка` и `Огляд` пациенту не показываются. Разрешенные материалы могут содержать текст, рекомендации, фото и видео.

## 5. Полная инструкция для врача

### 5.1. Вход врача

1. Открыть `Вхід для адміністрації`.
2. Ввести имя пользователя и пароль, созданные администратором.
3. Нажать `Увійти`.
4. Django проверит пароль и роль.
5. Если это врач, откроется кабинет врача; если администратор, откроется панель управления.

`Назад` возвращает на главную. Форма восстановления доступа не отправляет автоматические письма: она сообщает, что для восстановления нужно обратиться к администратору.

### 5.2. Обзор врача

Верхние вкладки:

- `Огляд` - профиль и настройки врача.
- `Мої заявки` - только новые заявки, ожидающие решения.
- `Прийоми` - недельный рабочий список всех статусов.
- `Пацієнти` - карточки пациентов.

Основная профильная карточка:

- `Записати пацієнта` открывает ручную запись.
- `Редагувати профіль` меняет имя, специальность, телефон, фото и описание.
- `Редагувати місця прийому` открывает адреса клиник и кабинетов.
- `Редагувати графік` открывает недельный график.
- `Редагувати послуги` открывает список услуг.
- `Редагувати новини` открывает публикации врача.

### 5.3. Мои заявки

Тут показываются только заявки со статусом `Нова заявка` именно этого врача. Они сгруппированы по дням и отсортированы по времени.

- Поле фильтра ищет по пациенту, телефону, возрасту, услуге, дате, месту и статусу.
- Крестик очищает фильтр.
- Имя пациента можно нажать, чтобы сразу подставить его в фильтр.
- `Детальніше` открывает заявку.
- `Відкрити картку` открывает медицинскую карточку.
- Пагинация появляется автоматически при длинном списке.

### 5.4. Приемы по неделям

Вверху написан диапазон недели без года, например `Тиждень з 20.07 по 26.07`.

- Левая стрелка открывает предыдущую неделю.
- Правая стрелка открывает следующую неделю.
- Надпись `Поточний тиждень` отмечает текущую.
- Выходные врача без приемов вообще не показываются.
- Если старый прием остался в день вне нового графика, такой день все равно показывается с особой пометкой.
- Если в одном дне более 5 приемов, `Розгорнути` показывает остальные, а повторное нажатие сворачивает.
- `Записати на цей день` открывает ручную запись с готовой датой.
- `Записати між прийомами` появляется только там, где стандартный слот можно безопасно разделить пополам.
- `Детальніше` открывает прием.
- `Відкрити картку` открывает пациента.

Цвета помогают отличить новые заявки, подтвержденные, завершенные, перенос, отмену и отказ.

### 5.5. Детальная заявка врача

Слева находятся пациент, возраст, телефон, услуга, дата, время, длительность, место, причина и медиа. Справа находится список всех приемов врача на этот день; текущая открытая запись выделена, а реально идущий сейчас прием получает отдельный акцент.

Для новой заявки:

- Поле `Тривалість прийому, хвилин` принимает значение, кратное длительности слота этого дня.
- `Підтвердити заявку` проверяет весь выбранный интервал и создает подтвержденный прием.
- `Відхилити заявку` ставит статус отказа и освобождает время.
- `Перенести прийом` раскрывает форму нового дня, времени и длительности.

Для подтвержденного приема:

- `Перенести прийом` отправляет предложение пациенту.
- `Скасувати прийом` отменяет будущий прием.
- `Відкрити картку пацієнта` открывает историю и заметки.

### 5.6. Ручная запись пациента врачом

Календарь даты показывает все числа месяца, но разрешает нажимать только рабочие дни из графика врача. Выходные и дни без сохраненного рабочего графика серые и недоступные. Для пациента минимальная дата — завтра, а врач при ручной записи может выбрать сегодняшний рабочий день. Скрипт `working_date_picker.js` отвечает только за удобное отображение; `booking()` и `doctor_book_patient()` повторно проверяют график на сервере и отклоняют подставленную вручную нерабочую дату.

1. Выбрать дату и время.
2. Начать вводить имя, фамилию или номер в поиске зарегистрированных пациентов.
3. Выбрать найденного пациента. Поля имени, фамилии и телефона исчезнут.
4. Или нажать `Новий пацієнт` и заполнить эти поля вручную.
5. Выбрать услугу через живой фильтр.
6. Указать длительность, кратную слоту текущего дня.
7. Заполнить причину.
8. Нажать `Записати пацієнта`.

Если врач вручную вводит телефон существующего зарегистрированного аккаунта, форма не создает дубликат и просит выбрать найденного пациента. Если номер принадлежит старой незарегистрированной карточке этого врача, карточка используется повторно.

При разделении 20-минутного слота исходный прием сокращается до 10 минут, а новый создается на вторую половину. Это разрешено только врачу и только при выполнении всех проверок.

### 5.7. Пациенты и карточки

Фильтр ищет по имени, фамилии, телефону и возрасту. Список показывает возраст, последний визит, следующий визит и количество записей.

В карточке пациента:

- `Зберегти нотатки` сохраняет общую внутреннюю заметку врача.
- Форма `Новий запис у картці` добавляет тип, заголовок, описание, рекомендации, фото и видео.
- `Додати запис до картки` сохраняет материал.
- `Видалити` удаляет конкретную запись.
- `Видалити фото` и `Видалити відео` удаляют отдельный файл.
- `До списку карток` возвращает в раздел пациентов.

Типы `Лікування` и `Рекомендації` видит пациент. `Нотатка` и `Огляд` остаются внутренними.

### 5.8. Места приема

Каждое место состоит из названия клиники или кабинета, города и адреса.

- Фильтр ищет место только по городу или адресу. Название клиники или кабинета
  остается видимым, но в поиске не участвует.
- `Додати місце` сохраняет новое место.
- `Редагувати` открывает его в форме.
- `Зберегти зміни` обновляет место и адреса связанных дней графика.
- `Скасувати` прекращает редактирование.
- `Видалити` работает только если место не используется в графике.

### 5.9. График

- `Додати день` раскрывает форму только для дней, которых еще нет в графике.
- Когда сохранены все семь дней недели, кнопка `Додати день` исчезает.
- Карандаш без фона возле строки открывает редактирование конкретного дня.
- При редактировании форма намеренно пустая: старое место, рабочее время и
  длительность слота не подставляются. Врач заполняет новый вариант с нуля.
- `Додати місце` ведет в справочник адресов.
- `До профілю` возвращает в обзор.
- `Зберегти графік` создает новый или полностью заменяет выбранный день недели.

Поля дня:

- день недели;
- место приема из сохраненных вариантов;
- начало и конец рабочего времени;
- длительность одного слота;
- готовые слоты обеденного перерыва;
- галочка рабочего дня.

Варианты обеда появляются после заполнения рабочего времени и длительности
слота. Например, при шаге 20 минут показываются `13:00-13:20`,
`13:20-13:40` и так далее. Можно отметить несколько вариантов, но они должны
идти подряд. Сервер переводит их в начало и общую длительность обеда, а затем
убирает этот интервал из времени, доступного пациентам.

На одного врача может быть только одна настройка для каждого дня недели.

### 5.10. Услуги

- `Додати нову послугу` раскрывает форму новой услуги.
- Фильтр ищет по названию, описанию и доступности.
- Стрелка вверх перемещает услугу выше.
- Стрелка вниз перемещает ее ниже.
- `Приховати від пацієнтів` немедленно убирает услугу из онлайн-записи.
- `Показувати пацієнтам` возвращает ее в онлайн-запись.
- `Переглянути сторінку` открывает публичный вид.
- `Редагувати` раскрывает поля прямо в этой услуге.
- `Зберегти зміни` сохраняет текст, стоимость, видимость и новые файлы.
- `Видалити фото` или `Видалити відео` удаляет отдельный материал.
- `Видалити` удаляет услугу. Старые приемы сохранятся, но поле услуги у них станет пустым.

Примерная стоимость необязательна. Пациент при выборе услуги цену в списке не видит.

### 5.11. Новости врача

- `Зберегти новину` создает новую публикацию или сохраняет редактирование.
- `Редагувати` открывает существующую публикацию.
- `Скасувати` выходит из редактирования.
- `Видалити` удаляет новость.
- Галочка публикации определяет, видят ли новость посетители.

## 6. Полная инструкция для администратора

### 6.1. Обзор панели

Вкладки:

- `Огляд` - основная панель.
- `Користувачі` - переход к списку пользователей на этой же странице.
- `Додати лікаря` - создание аккаунта врача.
- `Контент сайту` - главная страница и оформление.
- `Telegram-повідомлення` - ручное сообщение всем подключенным пользователям или одному человеку.
- `Системні налаштування` - стандартная Django admin.

Быстрые кнопки:

- `Додати лікаря`;
- `Змінити головну сторінку`;
- `Надіслати повідомлення`.

Счетчики показывают активных пациентов, врачей, общее число записей и новые заявки.

### 6.2. Пользователи

Живой фильтр ищет по имени, логину, телефону, роли и состоянию.

- `Редагувати` меняет логин, имя, фамилию, телефон и роль-доступные данные.
- `Архівувати` устанавливает `is_active=False`. История и медицинские записи остаются.
- `Відновити` снова включает аккаунт.
- `Видалити назавжди` доступно только для уже архивированного пациента.

Нельзя архивировать или удалить собственный аккаунт администратора. Врача и администратора нельзя окончательно удалить этой кнопкой. При удалении пациента связь старых приемов с аккаунтом становится пустой, но снимки имени, телефона, приемы и медицинская история сохраняются.

### 6.3. Добавление врача

Администратор заполняет логин, пароль, имя, фамилию, специальность, телефон, фото и описание. `Створити акаунт лікаря` создает одновременно:

1. стандартного Django-пользователя;
2. профиль с ролью врача;
3. объект врача со специальностью и контактами.

После создания интерфейс показывает логин. Пароль нужно безопасно передать врачу.

### 6.4. Контент сайта

**Оформлення**

- название клиники;
- логотип, включая проверенный SVG;
- общий фон;
- анимационный эффект;
- собственное изображение частиц;
- `Зберегти оформлення`.

**Верхні фотографії**

- стрелки вверх и вниз меняют порядок;
- `Редагувати` открывает фото и подпись;
- `Приховати` временно убирает с главной;
- `Показати` возвращает;
- `Видалити` удаляет;
- `Додати фотографію` создает новый слайд;
- `Зберегти зміни` обновляет выбранный;
- `Скасувати` закрывает редактирование.

**Новини**

- фильтр ищет заголовок, текст, автора и состояние;
- `Зберегти новину` создает или обновляет;
- `Редагувати`, `Скасувати`, `Видалити` выполняют соответствующие действия;
- новость без врача считается новостью клиники;
- новость с врачом считается новостью врача.

**Галерея**

- используются только загруженные администратором фотографии;
- `Зберегти фотографію`, `Редагувати`, `Скасувати`, `Видалити`;
- галочка публикации управляет видимостью.

`Переглянути сайт` открывает публичную страницу в новой вкладке.

### 6.5. Массовое Telegram-сообщение

Страница `Telegram-повідомлення` предназначена для ручных объявлений клиники.

1. `Усім підключеним користувачам` выбирает все активные аккаунты с действующей связью `TelegramConnection`.
2. `Одному користувачу` раскрывает список конкретных получателей. В списке показываются имя, роль и Telegram username или технический chat ID.
3. `Текст повідомлення` принимает до `3500` символов. Счетчик справа обновляется во время ввода.
4. `Надіслати повідомлення` обращается к Telegram Bot API и показывает тост с количеством успешных и неудачных доставок.

Архивные аккаунты и отключенные Telegram-связи в рассылку не входят. Введенный текст экранируется перед передачей в HTML-режим Telegram, поэтому символы `<`, `>` и `&` не могут сломать разметку. В журнале действий сохраняются адресат, счетчики доставки и короткий фрагмент текста. Медицинские фотографии, диагнозы и другие приватные сведения в массовую рассылку добавлять не следует.

Отправление выполняется сразу в обычном Django-запросе. Это простая схема для небольшой клиники. Если подключенных пользователей станет несколько тысяч, рассылку нужно перенести в фоновую очередь задач, чтобы администратор не ожидал завершения всех сетевых запросов в браузере.

### 6.6. Системная панель Django

Это техническая панель `/admin/`. Она позволяет напрямую редактировать таблицы. Пользоваться ей нужно осторожно: она менее дружелюбна и может обойти удобный рабочий сценарий. Для ежедневной работы лучше использовать обычную панель Orthosmile.

## 7. Все статусы заявки и приема

| Внутреннее значение | Украинская надпись | Что означает | Занимает время |
|---|---|---|---|
| `pending` | Нова заявка | Пациент отправил заявку, врач еще не решил | Да |
| `approved` | Підтверджено | Врач согласовал прием | Да |
| `completed` | Завершено | Время подтвержденного приема закончилось | Да для исторической проверки |
| `canceled` | Скасовано | Пациент, врач или администратор отменил | Нет |
| `rejected` | Відхилено | Врач отказал в заявке | Нет |
| `reschedule_proposed` | Очікує рішення пацієнта | Врач зарезервировал новое время и ждет пациента | Да |

Основной путь:

```text
Нова заявка -> Підтверджено -> Завершено
            -> Відхилено
            -> Очікує рішення пацієнта -> Підтверджено
                                         -> Скасовано
```

Отмена разрешена только для будущего активного состояния. Это проверяется не только кнопкой, но и сервером.

## 8. Правила времени и занятости

### 8.1. Слот

Слот - базовый шаг графика врача. Например, с 09:00 до 17:00 при слоте 20 минут получаются 09:00, 09:20, 09:40 и так далее.

### 8.2. Длительность

Пациент запрашивает один начальный слот, но врач решает фактическую длительность. Она должна быть кратна слоту дня: при слоте 20 минут допустимы 20, 40, 60 и так далее.

### 8.3. Что проверяет сервер

Перед сохранением сервер проверяет:

- существует ли рабочий график на день;
- является ли день рабочим;
- не прошло ли время;
- не выходит ли прием за конец рабочего дня;
- не пересекается ли он с обедом;
- не пересекается ли с любой активной записью врача;
- не пересекается ли с другой записью самого пациента к любому врачу;
- не достиг ли пациент лимита 2 самостоятельных активных записей на день;
- соответствует ли длительность слоту;
- не занял ли кто-то время между показом формы и нажатием кнопки.

Последний пункт решается транзакцией и ограничениями PostgreSQL. Поэтому два человека не должны успешно занять один стартовый слот одновременно.

### 8.4. Отмена и восстановление

При отмене статус меняется, и запись перестает блокировать график. При восстановлении все правила проверяются снова. Если место занято, восстановление невозможно.

### 8.5. Автоматическое завершение

При открытии рабочих страниц Django ищет подтвержденные приемы, время окончания которых уже прошло, и переводит их в `Завершено`.

## 9. Что такое Django

Django - это серверный веб-фреймворк на языке Python. Фреймворк можно представить как большой готовый набор деталей для сайта. Он уже умеет принимать запросы, работать с пользователями, проверять формы, обращаться к базе, защищать действия и строить HTML.

В проекте используется схема **Model - View - Template**:

- **Model** описывает данные. Например, модель `Appointment` описывает прием.
- **View** содержит действие. Например, функция `booking()` проверяет форму и создает заявку.
- **Template** описывает внешний HTML. Например, `booking.html` рисует форму записи.

Это немного отличается от классического названия MVC, но смысл тот же: данные, логика и внешний вид разделены.

### 9.1. Что Django делает автоматически

- читает адрес страницы;
- находит связанную Python-функцию;
- распознает текущего пользователя по cookie сессии;
- защищает POST-формы CSRF-токеном;
- проверяет поля формы;
- преобразует Python-объекты в SQL-запросы;
- подставляет данные в HTML-шаблон;
- хранит сообщения об успехе и ошибке до следующей страницы;
- обслуживает стандартную систему пользователей и администратора;
- выполняет миграции схемы базы.

### 9.2. GET и POST

В браузере чаще всего используются два вида запроса:

- `GET` просит показать страницу или данные. Он не должен менять важные данные.
- `POST` отправляет форму и меняет данные: создает, сохраняет, отменяет, удаляет.

Например, открытие `/doctor/services/` является GET. Нажатие `Додати послугу` отправляет POST.

### 9.3. Сессия и cookie

После входа Django создает серверную сессию. В браузере сохраняется маленькая cookie с идентификатором. Пароль в cookie не хранится. По идентификатору Django находит сессию и понимает, кто открыл страницу.

## 10. Как запрос проходит через сайт

Рассмотрим рабочий сервер:

```text
Телефон или компьютер
        |
        | HTTPS
        v
Nginx
        |
        | Unix-сокет
        v
Gunicorn
        |
        v
Django URL -> View -> Form/Model -> PostgreSQL
        |
        v
HTML-ответ -> Nginx -> браузер
```

Пошагово:

1. Пользователь открывает `https://orthosmile.duckdns.org/doctor/services/`.
2. DNS сообщает браузеру IP сервера.
3. Nginx принимает защищенное HTTPS-соединение.
4. Для `/static/` и `/media/` Nginx может отдать обычный файл сам.
5. Остальные запросы Nginx передает Gunicorn через `/run/medclinic/gunicorn.sock`.
6. Gunicorn передает запрос Django.
7. `medclinic/urls.py` передает адрес в `clinic/urls.py`.
8. Маршрут `doctor/services/` вызывает `doctor_services()`.
9. Декоратор `doctor_required` убеждается, что пользователь является активным врачом.
10. View читает данные, выполняет действие и вызывает шаблон.
11. Шаблон превращается в HTML.
12. Ответ возвращается браузеру.

## 12. Как устроена база данных

База данных похожа на набор связанных таблиц Excel, но с жесткими правилами и быстрым поиском. Каждая строка имеет уникальный числовой `id`. Связь `ForeignKey` хранит ссылку на строку другой таблицы.

### 12.1. Встроенный `User`

Django хранит логин, хеш пароля, имя, фамилию, технический email, активность, права администратора и дату входа. Настоящий пароль не хранится: хранится необратимый хеш.

### 12.2. `Profile`

Дополнение к `User` для пациента или роли:

- один профиль связан ровно с одним пользователем;
- `role` равен `patient` или `doctor`;
- `phone`;
- `photo` пациента;
- `age` от 1 до 120;
- непустой телефон пациента уникален на уровне базы.

### 12.3. `Doctor`

Данные врача:

- ссылка на `User`;
- специальность;
- телефон;
- загруженное фото;
- старое необязательное URL-поле фото;
- подробный текст о себе.

### 12.4. `DoctorWorkplace`

Сохраненное место работы конкретного врача: название, город, адрес. У одного врача не может быть двух мест с одинаковым названием.

### 12.5. `WorkSchedule`

Один день повторяющегося недельного графика:

- врач;
- место приема;
- номер дня от 0 для понедельника до 6 для воскресенья;
- снимок города и адреса;
- начало и конец;
- размер слота;
- время и длительность обеда;
- рабочий день или выходной.

Один врач имеет максимум одну запись графика на каждый день недели.

### 12.6. `MedicalService`

- врач-владелец;
- название;
- необязательная примерная стоимость;
- подробное описание;
- номер порядка;
- разрешение выбора пациентом.

`MedicalServiceImage` и `MedicalServiceVideo` позволяют одной услуге иметь несколько файлов.

### 12.7. `Appointment`

Главная таблица заявки или приема:

- врач и необязательная услуга;
- необязательная ссылка на зарегистрированного пациента;
- снимок имени, фамилии, телефона и технической почты;
- признак записи для другого человека;
- дата и время;
- снимок места;
- причина;
- длительность;
- статус;
- даты создания и подтверждения;
- старые и новые данные переноса.

Почему имя и телефон дублируются, если есть пользователь: это сохраняет историческую запись даже после изменения профиля или удаления аккаунта.

База запрещает две неотмененные записи одного врача с одинаковыми датой и стартовым временем. Более сложные пересечения по длительности дополнительно проверяет Python.

`AppointmentImage` и `AppointmentVideo` относятся к заявке и хранятся закрыто.

### 12.8. `DoctorPatientCard`

Это отдельная карточка пациента у конкретного врача. Один и тот же пациент может иметь разные карточки у разных врачей. Карточка содержит ссылку на аккаунт, снимки контактных данных и общие заметки врача.

Для зарегистрированного пациента действует уникальность пары врач + пациент. Для незарегистрированного - врач + телефон + имя + фамилия.

### 12.9. `PatientRecordEntry`

Одна расширенная запись врача в карточке:

- тип;
- заголовок;
- подробности;
- рекомендации;
- врач;
- карточка;
- необязательная связь с конкретным приемом;
- время создания и обновления.

К ней относятся `PatientRecordImage` и `PatientRecordVideo`.

### 12.10. Telegram-таблицы

- `TelegramConnection` связывает пользователя с уникальным `chat_id`.
- `TelegramLinkToken` хранит одноразовый код на 10 минут.
- `TelegramNotification` хранит попытку уведомления, результат и уникальный ключ, чтобы одно событие не отправлялось дважды.

### 12.11. Контент

- `ClinicSettings` хранит название, логотип, фон и эффект.
- `HomeHeroSlide` хранит верхние слайды и их порядок.
- `NewsPost` хранит новость клиники или врача.
- `GalleryImage` хранит одну фотографию галереи.

### 12.12. `AuditLog`

Журнал хранит кто, когда, над каким объектом и какое действие выполнил. Если аккаунт автора позже удален, само событие остается.

### 12.13. Что означает `on_delete`

- `CASCADE`: удаление владельца удаляет зависимые строки.
- `SET_NULL`: зависимая история остается, но ссылка становится пустой.

Например, удаление услуги не удаляет старый прием, потому что `Appointment.service` использует `SET_NULL`. Удаление пациента не удаляет приемы, потому что `Appointment.patient` тоже `SET_NULL`.

## 13. Как база была перенесена на PostgreSQL

### 13.1. Локальная база

Для простого запуска на Windows Django по умолчанию использует файл `db.sqlite3`. SQLite не требует отдельной программы: вся база находится в одном файле.

### 13.2. Почему production использует PostgreSQL

PostgreSQL лучше подходит для постоянно работающего сайта, одновременных запросов, транзакций, ограничений и резервных копий.

### 13.3. Что делает скрипт переноса

`deploy/migrate-sqlite-to-postgresql.sh` выполняет перенос осторожно:

1. Создает отдельную защищенную папку резервной копии.
2. Копирует `.env` и `db.sqlite3`.
3. Выполняет `PRAGMA integrity_check` для SQLite.
4. Останавливает сайт и бота, чтобы данные не изменились посередине.
5. Делает финальную копию SQLite.
6. Выгружает данные Django в JSON, исключая автоматически создаваемые разрешения.
7. Подсчитывает строки всех моделей.
8. Генерирует случайный пароль базы.
9. Создает локальную роль PostgreSQL `medclinic`.
10. Создает базу `medclinic` в UTF-8.
11. Выполняет все миграции, создавая таблицы.
12. Загружает JSON в PostgreSQL.
13. Снова считает строки и сравнивает результаты.
14. Только после успешного сравнения переключает `.env` на PostgreSQL.
15. Устанавливает ежедневные резервные копии.
16. Запускает сайт и бота.
17. Проверяет Django, сайт, тип базы и читаемость архива.

При ошибке скрипт возвращает старый `.env` и запускает сервисы обратно. Старый SQLite не удаляется.

### 13.4. Миграции Django

Файлы `clinic/migrations/0001...0029` являются историей изменения схемы. `python manage.py migrate` смотрит, какие миграции уже применены, и выполняет недостающие.

Миграция не является резервной копией. Она описывает структуру, но не сохраняет значения таблиц.

### 13.5. Резервные копии

Таймер запускается ежедневно примерно в 03:15 с небольшой случайной задержкой. Команда `pg_dump` создает архив в `/opt/backups/postgresql`. Копии старше 14 дней удаляются автоматически.

## 14. Как работает Google-вход

Используется пакет `django-allauth` и провайдер Google OAuth 2.0.

### 14.1. Поток входа

1. Пользователь нажимает `Увійти через Google`.
2. Django создает OAuth-запрос и перенаправляет на Google.
3. Google показывает название приложения и список аккаунтов.
4. После согласия Google возвращает браузер на callback.
5. Callback `https://orthosmile.duckdns.org/accounts/google/login/callback/` должен в точности совпадать с разрешенным URI в Google Cloud.
6. `django-allauth` проверяет ответ Google и получает подтвержденные профиль и email.
7. Django находит или создает пользователя и сессию.

### 14.2. Что хранится

Сайт не получает пароль Google. Он хранит Django-пользователя и запись social account. Email используется технически для уникальности и связи, но специально не показывается в пользовательских профилях.

### 14.3. Особые правила проекта

- Врач и администратор не могут входить через Google.
- Новый Google-пользователь получает роль пациента.
- Если сначала введен телефон, после входа связываются незарегистрированные записи.
- Имя и фамилия от врача имеют приоритет при такой привязке.
- Пациент без Google не проходит декоратор `patient_required`.

### 14.4. Ошибка `redirect_uri_mismatch`

Она означает, что адрес callback в запросе не совпадает с Google Cloud. Нужно проверить:

- домен без опечатки;
- протокол именно `https`;
- полный путь `/accounts/google/login/callback/`;
- отсутствие лишнего или недостающего слеша;
- правильные Client ID и Secret в `Social applications`;
- что приложение связано с сайтом `orthosmile.duckdns.org` в Django Sites.

## 15. Как работает регистрация по телефону

Телефон сам по себе не является окончательной авторизацией. Он нужен, чтобы найти старые ручные записи и показать временный кабинет.

### 15.1. Состояние до Google

Нормализованный телефон сохраняется в Django-сессии как `patient_claim_phone`. Пользователь еще не считается авторизованным пациентом.

Сайт ищет:

- `Appointment` без связанного пользователя с таким телефоном;
- `DoctorPatientCard` без пользователя с таким телефоном.

Из последней найденной записи берутся имя и фамилия для временного профиля.

### 15.2. Завершение

После Google-входа `claim_patient_complete()`:

1. проверяет роль;
2. проверяет наличие Google-связи;
3. проверяет, что аккаунт не содержит другой телефон;
4. повторно проверяет уникальность номера;
5. берет имя и фамилию врача, если они существуют;
6. в одной транзакции сохраняет телефон и связывает приемы и карточки;
7. удаляет телефон из сессии.

## 16. Как работает Telegram-бот

Бот: `@myclinic_ua_bot`.

### 16.1. Почему не вводится username или телефон Telegram

Сайт создает ссылку вида `https://t.me/myclinic_ua_bot?start=ОДНОРАЗОВЫЙ_КОД`. Telegram сам сообщает боту надежный числовой `chat_id`. Username может меняться и может отсутствовать, а `chat_id` подходит для доставки.

### 16.2. Привязка

1. Пользователь нажимает `Приєднати Telegram-бота`.
2. Старые неиспользованные коды пользователя удаляются.
3. Создается случайный код на 10 минут.
4. Открывается Telegram.
5. Пользователь нажимает Start.
6. Бот получает `/start код`.
7. Код блокируется транзакцией и проверяется.
8. Создается или обновляется `TelegramConnection`.
9. Код помечается использованным.

Один Telegram chat не может быть одновременно активно связан с двумя профилями.

### 16.3. Команды

- `/start код` связывает профиль.
- `/start` у уже связанного пользователя отвечает, что он уже зарегистрирован.
- `/start` без связи объясняет, что привязку нужно начинать на сайте.
- `/help` показывает такую же подсказку.
- `/stop` выключает уведомления.

### 16.4. Какие уведомления отправляются

- врачу о новой или восстановленной заявке;
- пациенту о подтверждении, отказе, отмене врачом или администратором;
- пациенту о предложении нового времени;
- врачу о принятии, отказе или отмене со стороны пациента;
- только пациенту напоминание о завтрашнем подтвержденном приеме.
- ручное объявление администратора всем активным Telegram-подключениям или одному выбранному пользователю.

В уведомлении врачу о новой заявке находятся три кнопки:

- `✅ Прийняти` подтверждает заявку со стандартной длительностью текущего дня;
- `❌ Відхилити` отклоняет заявку;
- `Деталі на сайті` открывает защищенную страницу с полной информацией.

Перед выполнением бот проверяет, что Telegram принадлежит именно этому врачу,
заявка еще ожидает решения, время не прошло, интервал свободен и у пациента нет
другого приема одновременно. Решение выполняется в транзакции, записывается в
`AuditLog` и отправляется пациенту. После успешного действия две кнопки решения
исчезают. Менять длительность приема через Telegram нельзя: для этого врач
открывает подробности на сайте.

### 16.5. Защита от повторов

Каждое событие получает уникальный `event_key`. Если сообщение уже имеет статус `sent`, повторная попытка ничего не отправляет.

### 16.6. Напоминания

Бот раз в минуту проверяет необходимость напоминаний. До 18:00 они не отправляются. После 18:00 выбираются подтвержденные приемы на завтра. Уникальный ключ не позволяет отправить одно напоминание повторно.

### 16.7. Как бот работает на сервере

Сервис `medclinic-bot` выполняет:

```bash
/opt/medclinic/.venv/bin/python manage.py run_telegram_bot
```

Команда использует long polling: удаляет webhook, регулярно спрашивает Telegram о новых сообщениях и восстанавливается после временной ошибки сети или базы через 5 секунд.

В проекте также существует защищенный webhook URL, но production-сервис использует long polling. Одновременно применять оба способа нельзя.

## 17. Фотографии, видео и защита медицинских файлов

### 17.1. Лимиты

- Фото: до 8 МБ каждое.
- Фото: до 6 файлов за одну загрузку или на одну услугу.
- Разрешение фото: до 40 миллионов пикселей.
- Видео: до 50 МБ каждое.
- Видео: до 2 файлов за одну загрузку или на одну услугу.
- Видео: MP4, WEBM или MOV.
- Логотип: до 2 МБ, PNG, JPG, JPEG, WEBP, GIF или SVG.

### 17.2. Проверка содержимого

Расширения недостаточно. Pillow пытается реально прочитать изображение. Видео проверяется по заголовку файла. SVG разбирается как XML, запрещает скрипты, внешние ссылки, обработчики событий, опасные элементы и конструкции.

### 17.3. Публичные и закрытые файлы

Публичные фото врачей, фон, новости и галерея находятся в `media/` и могут отображаться гостям.

Медицинские файлы заявки и карточки находятся в `private_media/`. Nginx не публикует эту папку. Django выдает файл через `/private-media/...` только после проверки:

- администратора;
- врача-владельца;
- связанного пациента с Google;
- типа медицинской записи, разрешенного пациенту.

### 17.4. Удаление файла

При удалении строки фотографии или видео сигнал Django удаляет и физический файл, чтобы диск не заполнялся мусором.

### 17.5. Проверка остальных полей

Общие числовые и текстовые пределы собраны в `clinic/validators.py`, чтобы формы и модели использовали одинаковые значения.

- Украинский телефон можно написать как `0501234567`, `+380501234567` или с обычными пробелами и дефисами. После удаления оформления должно остаться ровно 12 цифр, начинающихся с `380`; в формах номер сохраняется как `+380XXXXXXXXX`.
- Примерная стоимость услуги необязательна. Если врач ее указывает, допустим диапазон от 0 до 1 000 000 гривен. Ограничение действует в форме, модели и `CHECK`-ограничении PostgreSQL.
- Возраст пациента находится в диапазоне от 1 до 120 лет.
- Прием не может длиться больше 1440 минут, а один стандартный слот - больше 480 минут. Дополнительная логика графика требует, чтобы слот помещался в рабочий день, а длительность приема соответствовала шагу расписания.
- Причина обращения ограничена 2000 символами. Описание услуги, заметки врача, подробности и рекомендации медицинской записи ограничены 5000 символами. Текст новости ограничен 10000 символами.
- Имена, фамилии, названия, города, адреса, email и URL имеют тип и максимальную длину в формах или моделях Django. Пустая строка из одних пробелов не считается заполненным обязательным текстовым полем.

Проверка выполняется в несколько слоев. HTML-атрибуты помогают сразу увидеть предел в браузере. Django-форма не принимает подмененный запрос. Валидаторы модели действуют в панели администратора. Критичное ограничение стоимости дополнительно не дает самой базе сохранить сумму выше миллиона. Ошибка показывается на украинском возле конкретного поля.

## 18. Как работает интерфейс в браузере

HTML задает смысл и структуру. CSS задает внешний вид. JavaScript добавляет локальную интерактивность.

### 18.1. Фильтры

`live_filter.js` заранее индексирует текст строк. При каждом символе он:

1. приводит текст к нижнему регистру;
2. убирает диакритические различия;
3. разбивает запрос на слова;
4. оставляет строки, содержащие каждое слово;
5. обновляет счетчик;
6. показывает пустое состояние;
7. пересчитывает страницы.

Это фильтр уже загруженных данных. Он не отправляет новый запрос серверу.

### 18.2. Пагинация

По умолчанию показывается 10 подходящих элементов. JavaScript создает кнопки предыдущей, номеров страниц и следующей. В некоторых небольших пациентских секциях пагинация используется без фильтра.

### 18.3. Тост-сообщения

Django записывает сообщение в сессию. `base.html` выводит его в правом нижнем углу. Успешное сообщение с `data-auto-dismiss` исчезает примерно через 1,8 секунды плюс анимация. Ошибки остаются, чтобы пользователь успел прочитать.

### 18.4. Мобильная версия

На узком экране:

- блоки становятся одной колонкой;
- шапка и вкладки могут прокручиваться горизонтально;
- размеры шрифта и отступы уменьшаются;
- слоты времени помещаются по несколько в строке;
- широкие таблицы получают собственную прокрутку;
- кнопки остаются достаточно крупными для нажатия, но не занимают весь экран без необходимости.

### 18.5. Типографика и безопасные отступы

Заголовки используют увеличенную высоту строки, поэтому две строки текста не накладываются друг на друга. Декоративная линия под заголовком имеет собственный нижний отступ и не пересекает следующую подпись. Панели фильтров получили внутренние отступы, а длинные подписи переносятся внутри доступной ширины. Эти правила одинаково действуют на компьютере и телефоне.

### 21.4. Gunicorn

Gunicorn запускает два рабочих процесса Django, слушает Unix-сокет и автоматически перезапускается после сбоя. Сервис не запускается от root, что уменьшает последствия ошибки.

- Telegram token и username;
- адрес сайта.

## 24. Частые проблемы и их решение

### 24.1. PowerShell запрещает Activate.ps1

Для текущего окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
```

### 24.2. `No module named django`

Не активировано окружение или не установлены пакеты:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 24.3. `no such table` или ошибка отсутствующей колонки

```powershell
python manage.py migrate
```

### 24.4. CSS пропал на сервере

```bash
cd /opt/medclinic
/opt/medclinic/.venv/bin/python manage.py collectstatic --noinput
systemctl restart medclinic nginx
```

Затем обновить страницу без кеша.

### 24.5. Ошибка Google 400

Проверить точный callback, домен в Django Sites, Social application и HTTPS proxy-настройку. Для текущего домена callback:

```text
https://orthosmile.duckdns.org/accounts/google/login/callback/
```

### 24.6. Telegram-бот не отвечает

```bash
systemctl status medclinic-bot
journalctl -u medclinic-bot -n 100 --no-pager
systemctl restart medclinic-bot
```

Также проверить token и username в `.env`, доступ сервера к `api.telegram.org` и отсутствие второго процесса с тем же токеном.

### 24.7. Ошибка 502 Bad Gateway

Обычно Nginx не может соединиться с Gunicorn:

```bash
systemctl status medclinic
journalctl -u medclinic -n 100 --no-pager
systemctl restart medclinic
```

### 24.8. Ошибка 500

Посмотреть журнал Django. Частые причины: непримененная миграция, неправильный `.env`, ошибка шаблона или недоступная база.

### 24.9. База недоступна

```bash
systemctl status postgresql
sudo -u postgres psql -d medclinic -c 'SELECT 1;'
```

Нельзя публиковать пароль базы или открывать порт 5432 в интернет без отдельной необходимости.

### 24.10. Файл не загружается

Проверить размер, формат, реальное содержимое и лимит количества. Для большого видео также учитывать лимит Nginx 55 МБ.

### 24.11. Сайт показывает старый дизайн

На сервере выполнить `collectstatic`, затем перезапустить сервис и очистить кеш браузера. Статические файлы кешируются до 7 дней.

## Короткая памятка владельцу

1. Для пациента используется Google, для врача и администратора общий логин с паролем.
2. Врачей создает администратор.
3. Сначала врач создает места, затем график, затем услуги.
4. Пациент отправляет заявку, врач выбирает длительность и подтверждает.
5. Любое время перед сохранением повторно проверяется сервером.
6. Медицинские файлы закрыты от гостей.
7. Telegram связывается только одноразовой кнопкой сайта.
8. Секреты находятся только в `.env`.
9. После изменения моделей нужны `makemigrations` и `migrate`.
10. После изменения CSS или JavaScript на сервере нужен `collectstatic`.
11. Перед важным обновлением базы нужна резервная копия.
12. При проблеме сначала смотреть `systemctl status` и `journalctl`.
